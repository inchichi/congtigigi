# LLM 이벤트 코드 적용 마일스톤

## 목적

LLM으로 생성한 이벤트를 게임에 바로 적용하지 않고, 난이도와 위험도에 따라 단계적으로 반영한다.

이 문서는 다음 목표를 위한 기준을 정리한다.

- 생성된 JSON과 코드의 안정성 확보
- 기존 게임 구조 훼손 최소화
- 난이도별 적용 가능 범위 분리
- 사용자 검토와 자동 적용 사이의 중간 검증 단계 마련

## 기본 원칙

1. LLM이 만든 결과는 바로 게임에 반영하지 않는다.
2. 먼저 JSON 검증을 통과해야 한다.
3. 기존 게임 자산만으로 가능한 경우를 우선 적용한다.
4. 새 NPC, 새 아이템, 맵 수정처럼 위험도가 큰 작업은 더 높은 마일스톤에서만 허용한다.
5. 기존 파일을 직접 덮어쓰기보다 runtime 등록 또는 미리보기 우선 방식을 사용한다.

## 마일스톤 정의

### M0. 스키마 통과

가장 기본 단계다.

- JSON 형식이 올바른지 확인한다.
- 필수 필드가 있는지 확인한다.
- 존재하지 않는 맵, NPC, 아이템을 사용하지 않았는지 검사한다.
- 이 단계가 통과되지 않으면 코드 생성 버튼을 비활성화한다.

허용 범위:

- JSON 파싱
- JSON 스키마 검증
- 참조 ID 검증

비허용 범위:

- 코드 생성
- 게임 적용
- 런타임 등록

### M1. 읽기 전용 미리보기

생성된 내용을 화면에만 보여주는 단계다.

- 생성된 JSON을 미리보기로 표시한다.
- 생성된 코드를 텍스트로만 보여준다.
- 게임 상태는 변경하지 않는다.

허용 범위:

- JSON 초안 표시
- 코드 미리보기 표시
- 사용자 검토

비허용 범위:

- runtime 등록
- NPC 상태 변경
- 퀘스트 적용

### M2. 런타임 등록

생성된 이벤트를 메모리 안에서만 등록하는 단계다.

- `DynamicEventManager` 같은 런타임 레지스트리에 이벤트를 추가한다.
- 파일을 덮어쓰지 않는다.
- 새로고침 전까지 유지되는 임시 등록으로 본다.

허용 범위:

- runtime registry 등록
- 이벤트 정의 추가
- 코드 객체 관리

비허용 범위:

- 실제 파일 저장
- 맵 구조 수정
- 대규모 시스템 변경

### M3. 비파괴적 게임 적용

게임 내에서 비교적 안전한 요소만 바꾸는 단계다.

- NPC 대사 변경
- 말풍선 변경
- 퀘스트 로그 갱신
- 간단한 보상 표기

허용 범위:

- 대화형 이벤트
- 기존 NPC 설정 업데이트
- 되돌리기 쉬운 UI/텍스트 반영

비허용 범위:

- 새 자산 생성
- 맵 레이아웃 변경
- 복잡한 이벤트 체인 생성

### M4. 제한된 실제 반영

실제 게임 상태를 바꾸는 범위를 넓히는 단계다.

- 단일 NPC 이벤트 등록
- 보상 아이템 연결
- 특정 맵 진입 이벤트 연결
- 퀘스트 시작/완료 연동

허용 범위:

- NPC 신규 연결
- 기존 아이템 사용
- 한 단계 퀘스트 연동

주의 사항:

- 기존 시스템과의 충돌 가능성이 있다.
- 추가 검증과 미리보기가 필요하다.

### M5. 고위험 반영

가장 높은 단계다.

- 맵 구조 수정
- 다중 이벤트 연쇄
- 새 NPC/새 아이템 추가
- 기존 이벤트 시스템 코드 수정

허용 범위:

- 파일 수정
- 시스템 구조 변경
- 새 자산 생성 필요 작업

필수 조건:

- 명시적 사용자 확인
- 더 엄격한 검증
- 롤백 전략

## 항목 난이도 분류

### 쉬움

- 대사 추가
- 말풍선 수정
- 퀘스트 설명 텍스트 수정

### 보통

- 단일 NPC 이벤트 등록
- 보상 아이템 연결
- 단일 맵 트리거 이벤트

### 어려움

- 새 NPC 생성
- 새 아이템 필요
- 퀘스트 상태와 연동되는 연쇄 이벤트

### 위험

- 맵 구조 변경
- 여러 파일 동시 수정
- 기존 이벤트 시스템 수정

## 추천 적용 흐름

1. JSON 생성
2. JSON 검증
3. 마일스톤 판정
4. 코드 미리보기
5. 런타임 등록
6. 게임 적용

이 흐름을 통해 사용자는 다음을 확인할 수 있다.

- 지금 생성된 결과가 어디까지 안전한지
- 어떤 작업이 위험한지
- 어떤 단계에서 버튼을 활성화해야 하는지

## 패널에 넣을 수 있는 필드 예시

```json
{
  "event_id": "christmas_event",
  "difficulty": "easy",
  "milestone": "M3",
  "requires_new_asset": false,
  "apply_mode": "runtime_only"
}
```

또는 더 세분화해서:

```json
{
  "milestone": {
    "level": 3,
    "label": "비파괴적 게임 적용",
    "allowed_actions": ["dialogue", "npc_message", "quest_log"],
    "blocked_actions": ["map_edit", "new_asset_creation"]
  }
}
```

## 현재 프로젝트에 맞는 해석

이 프로젝트에서는 다음처럼 보는 것이 적절하다.

- `M0`: JSON 자체가 맞는지
- `M1`: 화면에서 검토할 수 있는지
- `M2`: 런타임 레지스트리에 올릴 수 있는지
- `M3`: 현재 씬에 안전하게 적용할 수 있는지
- `M4`: 퀘스트와 보상까지 연결 가능한지
- `M5`: 실제 파일과 자산까지 수정하는지

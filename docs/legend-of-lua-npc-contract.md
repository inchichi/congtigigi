# legend-of-lua NPC 생성 계약 (에디터 ↔ 게임)

에디터(시나리오 공방)가 자연어로 **새 NPC**를 만들어 legend-of-lua에 더하기 위한 규약이다.
퀘스트 계약([legend-of-lua-quest-contract.md](legend-of-lua-quest-contract.md))과 평행하지만, NPC는
기존 배치 엔티티를 가리키는 게 아니라 **게임에 없던 캐릭터를 생성**한다.

> **이번 범위:** 에디터 검증 → 카탈로그 인식 → **Lua 출력(빌드 산출물)** 까지. 실행 중인 게임에
> NPC를 라이브로 스폰하는 것은 **포함하지 않는다**(게임-쪽 배선 필요 — 아래 §3).

## 1. 에디터가 만드는 것

- 구조화 NPC JSON([luaNpcSchema.ts](../src/editor/luaNpcSchema.ts))을 생성하고, 같은 모듈의
  검증기로 **결정적 검증**한다(맵 실존·외형 실존·id 충돌 없음).
- 검증을 통과하면 그 NPC를 에디터의 맵 엔티티로 주입해
  ([luaNpcCodeGenerator.ts](../src/editor/luaNpcCodeGenerator.ts) `convertLuaNpcToGameEntity`),
  트리와 퀘스트 카탈로그([luaQuestCatalog.ts](../src/editor/luaQuestCatalog.ts))가 **배치된 NPC처럼
  인식**한다 → 곧바로 퀘스트 기버로 쓸 수 있다.
- 동시에 legend-of-lua 호환 **Lua 모듈**을 렌더한다(미리보기/복사/내보내기).

## 2. Lua 산출물 (drop-in 데이터)

`renderGeneratedLuaNpcModule`이 내는 모듈은 게임이 `require`로 불러 NPC를 스폰/등록할 수 있는 데이터다:

```lua
-- Generated by the Legend of Lua NPC editor
return {
  entity_id = "NPCs-herb_seller",   -- 배치 NPC와 같은 "{group}-{id}" 규칙(group=NPCs)
  npc_id = "herb_seller",
  name = "약초 상인",
  map = "town",                      -- 이 게임에 실재하는 맵(tmx 파일명)
  appearance = "character_villager_brown_tunic",  -- my-sample-rpg에서 빌려온 스프라이트
  position = { x = 8, y = 6 },       -- 타일 좌표
  dialogue = { "약초가 필요한가?" }, -- 상호작용 대사
  behavior = { type = "wander", radius = 3 },  -- "wander"(radius>0) | "stationary"(0)
}
```

- `appearance`는 my-sample-rpg의 `character_*` 스프라이트 id다(출처:
  `src/games/my-sample-rpg/assets/tilesets/tiny-dungeon-16.tsx`). 게임은 이 id를 자기 스프라이트로
  매핑한다(에셋 자체를 가져오는 것은 게임-쪽 몫).
- `behavior`는 my-sample-rpg의 Lua 컨트롤러(`wander-near-home` / `reply-with-message`)와 같은 개념을
  데이터로 전달한다.

## 3. 게임-쪽 배선 (로컬 legend-of-lua 레포에 구현됨)

로컬 `legend-of-lua` 레포(별도 git)에 NPC 스폰/렌더/이동/대사를 실제로 배선했다. 핵심:

- **스프라이트**: `tools/slice_npc_sprites.py`가 my-sample-rpg의 `tiny-dungeon-16.png` 아틀라스에서
  `character_*` 타일을 잘라 `sprites/npc/<appearance>.png` 11종으로 저장. `src/startup/resources.lua`가
  `sprites.npc[<appearance>]`로 등록.
- **스폰/렌더/행동**: `src/levels/npc.lua`의 `spawnNPC(data)`가 외형 선택 + wander(반경 내 배회) +
  근접 시 머리 위 말풍선(dialogue 순환)을 처리. `src/update.lua`에 `npcs:update(dt)` 추가.
- **두 가지 스폰 경로**: (a) 맵의 `"NPC"` 오브젝트 레이어(`obj.type`=appearance,
  `properties.dialogue`="줄1|줄2", `properties.radius`), (b) **에디터 친화** 경로 —
  `src/levels/editorNPCs.lua`의 `editorNPCs[mapName] = { {name,x,y,appearance,dialogue={...},radius}, ... }`를
  `loadMap`이 `spawnEditorNPCs(mapName)`로 함께 스폰(TMX를 안 건드림).

### 에디터 → 게임 라이브 적용 (3경로)

에디터 'NPC 추가'로 만든 NPC를 게임에 띄우는 길은 셋이다:

1. **수동 붙여넣기(네이티브)**: 결과를 **복사**(미리보기=editorNPCs 항목) → `editorNPCs.lua`의 해당 맵
   배열에 붙여넣고 `love` 실행. 가장 확실.
2. **라이브 브리지(패널, love.js)**: '적용' → 에디터가 `kind:'spawn_npc'`를 iframe에 postMessage →
   host page `editor-bridge.js`가 Emscripten FS `/editor_inbox.lua`에 누적 기록 →
   게임 `pollEditorInbox(dt)`([editorInbox.lua](editorInbox.lua)는 게임 레포 `src/levels/`)가 읽어
   `spawnNPC`(플레이어 옆). **단 패널이 띄우는 packed 빌드를 재빌드해야 반영된다(아래).**
3. **라이브 브리지(네이티브, HTTP)**: '적용'은 localhost:17320으로도 보낸다 — 게임에 bridge.lua가
   있고 applyToGame이 `spawn_npc`를 처리하면 네이티브 창에 즉시 뜬다.

퀘스트 기버로도 쓰려면 엔티티를 `entity_id`로 식별해 `quest_runtime.on_talk(entity_id)`에
연결한다([quest-runtime.lua](quest-runtime.lua)).

### 확인(실행) 방법

에디터 패널은 `public/legend-of-lua/`의 **패킹된 love.js 빌드**라 소스 변경이 바로 안 보인다.
- **네이티브(빠름)**: `love D:\Seoyeon\Capstone\legend-of-lua` → 메뉴에서 test 맵 시작 → 플레이어
  양옆 NPC(배회+말풍선).
- **에디터 패널 라이브**: [legend-of-lua-love-js.md](legend-of-lua-love-js.md)대로 `.love` 압축 →
  `npx love.js`로 `public/legend-of-lua/`에 재빌드 → **`index.html`에 `editor-bridge.js` `<script>`
  한 줄 다시 추가**(빌드가 index.html을 새로 만듦 — [web/editor-bridge.README.md](web/editor-bridge.README.md))
  → dev 서버 재시작 → 새로고침. 이후 '적용'하면 패널 게임에 NPC가 라이브로 뜬다.

> 이 JS↔Lua 브리지(Emscripten FS 경유)는 작성자 환경에서 빌드·검증을 못 했다. 콘솔의
> `[editor-bridge]` 로그로 디버깅하고, 안 되면 경로 1(복사→editorNPCs.lua)로 폴백한다.

# Qwen + FLUX 테마 파이프라인

에디터에는 샘플 RPG를 기준으로 다음 통합 흐름이 구현되어 있습니다.

`자연어 테마 입력 → Qwen 테마 계획 생성 → 퀘스트 검증 → FLUX 스타일 대상 생성 → 게임 적용`

현재 통합 테마 JSON은 `my-sample-rpg` 전용 계약으로 고정되어 있습니다.

- `schema_version`: 현재 `1`
- `game_id`: `my-sample-rpg`
- `quest`: 현재 게임의 맵·NPC·몬스터·상점·아이템 ID만 사용
- `style_targets`: 추출된 맵 오브젝트 또는 정적 PNG만 사용

타일셋과 애니메이션 시트(`*-sheet.png`, `*-motion.png`)는 게임 런타임에서 공유되므로
스타일 대상 목록에서 제외합니다. 따라서 현재 단계에서 생성된 JSON은 다른 게임에
그대로 이식하는 포맷이 아니라, My Sample RPG에 적용하기 위한 검증 가능한 설계도입니다.

## Qwen 연결

Qwen은 OpenAI 호환 API 서버로 실행해야 합니다. Vite 개발 프록시는 다음 경로를 제공합니다.

`/api/qwen/v1/chat/completions`

기본적으로 `http://127.0.0.1:8000`으로 요청을 전달합니다. 다른 서버를 사용하려면 `QWEN_BASE_URL` 환경 변수를 설정한 뒤 Vite를 다시 실행하세요. Qwen 서버는 다음 API를 제공해야 합니다.

- `/v1/chat/completions`
- `/v1/models`

에디터 설정에서 로컬 Qwen 토큰으로 `qwen-local`을 입력합니다. 기본 모델은 `Qwen3.6-27B`이며, 모델 선택 메뉴에서 실제 배포된 모델 ID로 변경할 수 있습니다.

## 통합 생성 흐름

1. 샘플 RPG를 선택하고 테마를 입력합니다. 예: `달빛이 비치는 얼어붙은 마을에서 마법사가 잃어버린 수정을 찾아 달라고 부탁한다`
2. Qwen provider가 활성화된 상태에서 `테마 통합 생성`을 클릭합니다.
3. Qwen은 게임 프로필과 실제 퀘스트 ID, FLUX 에셋·오브젝트 ID 목록을 함께 전달받습니다.
4. 결과 보드에서 퀘스트, 미술 방향, FLUX 대상별 스타일 프롬프트를 확인합니다.
5. 에디터가 기존 퀘스트 드라이런 검증을 실행합니다. 검증을 통과해야 적용 버튼이 활성화됩니다.
6. 적용하면 선택된 각 대상에 FLUX를 실행하고, 퀘스트를 pending quest 저장소에 기록한 뒤 게임 프리뷰를 새로고침합니다.

## 테마 작업실

테마 통합 생성은 에디터의 일반 이야기 생성과 분리된 `editor.html?workspace=theme` 작업실 화면에서 진행합니다.

1. 자연어 프롬프트와 퀘스트 기버를 선택합니다.
2. `테마 방향` 결과를 확인하고 `이 결과 사용` 또는 `새로 만들기`를 선택합니다.
3. 같은 방식으로 `퀘스트`, `FLUX 스타일 대상`을 차례로 검토합니다.
4. 최종 JSON 검증을 통과한 뒤에만 `게임에 최종 적용`을 눌러 FLUX와 퀘스트를 반영합니다.

따라서 중간 결과가 마음에 들지 않으면 이미 승인한 이전 단계는 유지한 채 현재 단계만 다시 생성할 수 있습니다.

스타일 서비스는 에셋을 덮어쓰기 전에 원본을 백업합니다. 여러 FLUX 대상 중 일부가 실패하면 퀘스트는 저장하지 않지만, 이미 처리된 스타일 대상은 백업 상태로 남으며 기존 스타일 되돌리기 기능으로 복원할 수 있습니다.

## FLUX 실행 조건

Python 스타일 서비스는 FLUX.1-Kontext 모델 의존성과 모델 접근 권한이 필요합니다. `/health`가 `degraded`를 반환하면 테마 계획 생성과 검증은 테스트할 수 있지만, 이미지 스타일 적용은 실패합니다.
